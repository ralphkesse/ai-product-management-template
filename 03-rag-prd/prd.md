## Problem & user

RocketShip PMs need evidence-based prioritization. Juno turns noisy Slack, tickets, and strategy docs into a ranked, cited backlog they can defend.

## Solution overview

**Retrieval strategy:** Long Context

Justification: The revenue-weighted dissent guardrail only works if every flagged account is visible — RAG's top-k retrieval could silently drop the one high-ARR dissenter, exactly what the guardrail exists to prevent. Data also lives in one bounded pool (one product line's tickets, interviews, emails, plus one strategy doc), not scattered across stores worth searching. And V1's rolling daily window keeps volume small enough to fit in context outright, so a retrieval layer would add cost and risk without solving a scale problem V1 actually has.

## Retrieval requirements (RAG)

- **Sources:** Juno needs support tickets, interview/call notes, and sales or exec emails for one product line, plus account revenue/tier data so it can weigh dissent by account value, plus the optional strategy document. That's it — no other product lines, no company-wide history — because wider data reintroduces the bias problem this guardrail exists to preven
- **Chunking / indexing:** Keyword
- **Grounding rule:** Every insight shows its exact source quote and account — no bare category labels. Strategy Mode must cite the specific line in the document it's matching, and dissent used to override a call must show the account and ARR directly, not a vague summary.
- **Freshness:** Support tickets and interview/call notes should refresh daily — feedback signal goes stale fast, and a week-old ticket queue can already miss what's driving this week's decision. Account revenue/tier data can refresh weekly, since ARR and contract value don't shift day to day. The strategy document only updates when the PM re-uploads it — it's not something that needs a live sync.

## Requirements

| # | Requirement | Priority | Acceptance criteria |
|---|---|---|---|
| 1 | Retrieval quality and latency | Must | No ranked retrieval loop needed for the core corpus — that's the point of Long Context. The one retrieval call that exists is an exact-match account lookup (account ID → ARR/tier), so there's no top-K to tune there either. Target: p95 < 300ms for that lookup, p95 < 6s for the full transcript analysis call. |
| 2 | Fail-safe on empty retrieval | Must | When Juno can't find real evidence for something, it says so instead of making something up — no invented quotes, no guessed pillar match, no pretending a weak request is stronger than it is. Better an honest "not sure" than a confident wrong answer. |
| 3 | Grounded trust | Must | Every insight shows its exact source quote and account — no bare category labels. Strategy Mode must cite the specific line in the document it's matching, and dissent used to override a call must show the account and ARR directly, not a vague summary. |

## Out of scope

Decisions that cannot be cited to a source in the knowledge base. Anything Juno is not allowed to retrieve or act on without a human.
